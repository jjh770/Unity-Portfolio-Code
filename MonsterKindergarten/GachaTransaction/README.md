# GachaTransaction

가챠권 한 장을 필드의 슬라임 한 마리로 바꾸는 흐름입니다. 소비할 재화를 먼저 차감하면 필드가 가득 찼거나 생성에 실패했을 때 티켓만 사라질 수 있어, 검증과 소비·생성 순서를 별도 서비스로 명확히 했습니다.

## 파일

| 파일 | 역할 |
|---|---|
| [`GachaService.cs`](./GachaService.cs) | 해금·티켓·필드 공간·후보 검증 및 가챠 흐름 조율 |
| [`NormalGachaPool.cs`](./NormalGachaPool.cs) | 최고 해금 등급 기준의 가중치 풀과 결과 희귀도 계산 |
| [`EconomyTransactionService.cs`](./EconomyTransactionService.cs) | 재화 소비 뒤 행동 실패 시 롤백하는 공용 트랜잭션 순서 |

## 처리 순서

```text
가챠 해금 확인
→ 티켓 보유 확인
→ 메인 필드 공간 확인
→ 결과 후보 선택
→ 티켓 1장 소비
→ 슬라임 생성
→ 생성 실패 시 티켓 환불
→ 성공한 경우에만 가챠·피버 기록 반영
```

## 설계 포인트

- 랜덤 결과는 소비 전에 확정하지만, 실패 횟수와 도감 획득 기록은 실제 생성 성공 뒤에만 반영합니다.
- 튜토리얼 무료 뽑기는 일반 풀을 재사용하면서도 특별 판정과 피버 기록에서 제외합니다.
- 특별 슬라임은 별도 등급 풀이 아니라 같은 결과 풀에서 외형·포인트 배율만 달라지는 상태로 처리합니다.
- 이 서비스는 여러 저장 도메인의 진짜 저장소 원자성까지 보장하지 않습니다. 유료 재화가 추가되면 복구 저널 또는 서버 권위 설계가 별도로 필요합니다.
